# Recall-Boost Benchmark — LoCoMo

Lift from optional recall boosters measured on LoCoMo (Maharana
2024 — 5,882 turns, 1,982 questions with gold-evidence dia_ids).

**Baseline** = pure cosine over sbert `all-MiniLM-L6-v2`. All other
rows use the same corpus, same embedder; only the retrieval
strategy changes. "Lift R@5" is the absolute percentage-point
improvement over baseline.

## Results

| Strategy | R@1 | R@5 | R@10 | Retrieve (ms) | Lift R@5 |
| --- | ---: | ---: | ---: | ---: | ---: |
| baseline (cosine) | 0.098 | 0.238 | 0.285 | 13.3 | — |
| hybrid (alpha=0.3) | 0.207 | **0.415** | 0.456 | 28.5 | **+17.7 pp** |
| hybrid (alpha=0.5) | 0.181 | 0.380 | 0.445 | 28.3 | +14.2 pp |
| rerank (top-20) | 0.203 | 0.309 | 0.337 | 25.1 | +7.1 pp |
| hybrid + rerank (alpha=0.3, top-20) | **0.287** | **0.450** | **0.490** | 47.7 | **+21.2 pp** |

Relative deltas vs baseline:

- Hybrid alpha=0.3: **R@5 up 74%**, R@1 up 111%.
- Rerank top-20: R@5 up 30%, R@1 up 107%.
- **Hybrid + rerank: R@5 up 89%, R@1 up 193%** (nearly 3× the baseline R@1).

## Interpretation

The baseline row is exactly what any vector DB — Chroma, LanceDB,
Qdrant, Pinecone — reaches when using the same embedder and cosine
scoring. Every other row is a SOMA-side lift that those DBs don't
offer out of the box; they would require separate BM25 /
cross-encoder glue in userland.

**Hybrid search** is the biggest single-feature lift here (+17.7 pp
R@5 at alpha=0.3). LoCoMo queries are conversational and often hinge
on specific names/events/numbers that sbert's sub-word tokenization
disperses across a broader semantic neighborhood. BM25 catches those
exact-term signals while cosine catches the paraphrases; their union
is strictly larger than either alone. alpha=0.3 is sharper than 0.5
because in this corpus the lexical signal is noticeably stronger
than the paraphrase semantics — a tuning knob worth trying on your
own data.

**Cross-encoder re-ranking** alone is a more modest boost (+7.1 pp).
The bi-encoder (sbert) was strong enough that the top-20 cosine
candidates mostly already contained the gold evidence; re-ranking
redistributes it within that pool but can't rescue candidates that
never made the top-20. That said, R@1 *doubles* (0.098 → 0.203):
when the answer is in the pool, the re-ranker is much better at
picking the right one.

**Hybrid + rerank** compounds both: the BM25 leg widens the
candidate pool to include documents cosine never saw, and the
cross-encoder then precisely picks within that wider pool. R@5 lifts
21.2 pp absolute (89% relative); R@1 jumps from 0.098 to 0.287 (+193%
relative). This is the configuration any caller who cares about
recall should opt into.

## Latency cost

- Hybrid: +15 ms (BM25 search + union logic over 5.9K docs).
- Rerank (top-20, CPU cross-encoder): +12 ms.
- Both: +34 ms over baseline's 13.3 ms (still well under a typical
  sub-100 ms retrieval budget).

The cross-encoder is `cross-encoder/ms-marco-MiniLM-L-6-v2` (23 MB,
~0.6 ms/pair on this CPU). A bigger reranker (ms-marco-large) would
push recall higher at a few ms/pair penalty.

## How to opt in

```python
from soma.memory import MemoryLayer
from soma.memory.rerank import CrossEncoderReranker

mem = MemoryLayer.with_sbert()
# ...ingest your corpus...

mem.attach_reranker(CrossEncoderReranker())
hits = mem.retrieve(query, k=5, hybrid_alpha=0.3, rerank_top_n=20)
```

Default `mem.retrieve(query, k=5)` still does pure cosine for
backward compat and for matching peer systems. The recall-boost
knobs are strictly opt-in.

## Caveats

- These numbers are **LoCoMo-specific**. Conversational data with
  distinctive named entities is an ideal case for hybrid; corpora
  with less exact-term leverage (pure paraphrase retrieval, e.g.
  some BEIR splits) will show smaller hybrid lifts.
- Rerank latency scales with `rerank_top_n`; we tested 20.
- We compare only within-SOMA. A fair vs-Chroma comparison would
  require bolting comparable hybrid+rerank glue onto Chroma, which
  is a separate research project (pre-scoped in
  `paper-draft.md` §5).

## Reproduction

```bash
python -m benchmarks.run_recall_boost
```

Run time ~15-20 min (sbert ingest + 2 cross-encoder scoring passes
