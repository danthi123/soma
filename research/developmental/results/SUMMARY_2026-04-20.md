# SOMA validation summary — 2026-04-20

## The thesis being validated

**SOMA's built-in BM25+cosine hybrid retrieval is structurally better
than chroma's cosine retrieval**, and that advantage transfers
end-to-end: better retrieval → better LLM answers, measurably, on
multiple benchmarks with multiple LLMs.

The competitive positioning:
- Chroma ships cosine only. SOMA ships hybrid behind one API.
- Users replicating SOMA's behavior on chroma would wire BM25 + pool
  merge + score normalization themselves. Most don't.
- With SOMA, you get it for free.

## The numbers (all committed, reproducible)

### Retrieval quality

| Benchmark | Level | Embedder | Metric | SOMA win |
| --- | --- | --- | --- | --- |
| LoCoMo | turn (5882) | mxbai-large | R@5 hybrid+rerank | **+13%** vs chroma+rerank |
| LongMemEval | session (500×50) | sbert | R@5 hybrid | **+4.7% + 8.3× faster** vs chroma+rerank |

### End-to-end QA on LongMemEval (full N=500, qwen3.5:4b, strict prompt)

| Mode | F1 | EM | R@5 |
| --- | ---: | ---: | ---: |
| chroma cosine | 0.299 | 0.196 | 0.932 |
| **SOMA hybrid** | **0.368** | **0.242** | **0.980** |

**+22.8% F1, +23.5% EM, +5% R@5 absolute.** Roughly 1/4 of SOMA's
answers are exact matches to the gold string.

### Decomposition of the +23% F1 lift (causation findings, 2026-04-20)

Partitioning 500 items by (chroma_hit, soma_hit) and summing
(SOMA_f1 - chroma_f1) per cell:

| Cell | N | F1 lift | fraction |
| --- | ---: | ---: | ---: |
| (0,1) only SOMA retrieves | 30 | +11.49 | **34% (recall)** |
| (1,1) both retrieve gold | 460 | +22.55 | **66% (ranking)** |
| (1,0) only chroma retrieves | 6 | +0.11 | 0% |
| (0,0) neither retrieves | 4 | 0 | 0% |

Two mechanisms, independently measurable:
- **Recall (34%)**: BM25 catches keyword queries that cosine misses
  ("how many Mbps?", "what brand?", "how many minutes?").
- **Ranking (66%)**: LongMemEval sessions average 2491 tokens; the
  3.8K-token context budget only fits ~1.5 sessions. So gold at rank
  4-5 gets truncated out. SOMA's hybrid scoring pushes gold to rank
  1-2 where it fits. The IDK rate climbs monotonically with rank on
  chroma (rank 1: 19% IDK, rank 3: 100% IDK), directly measuring
  the truncation mechanism.

Global IDK rate: chroma 30.4% vs SOMA 18.2% on the same 500 items.
In (1,1) where both retrieve gold, chroma IDKs **62% more often**
than SOMA — strongest evidence for the ranking mechanism.

Details: `longmemeval_causation_findings.md`.

### Robustness checks

- **LLM-size invariance**: Same 200 items, same SOMA lift (+27%) on
  qwen3.5:4b and (+25%) on qwen3.5:9b. Retrieval advantage is not
  model-coupled.
- **Prompt-format invariance**: SOMA beats chroma by +10% with
  verbose prompting and +23% with strict prompting. The direction is
  the same; strict prompting removes a token-F1 verbosity confound.
- **Budget robustness**: At matched 3.8K-token context budget, SOMA
  beats chroma beats full_context truncation (F1 0.368 vs 0.299 vs
  0.029). SOMA's retrieval focus makes the context budget count.

## What's honest that wasn't initially

1. **The N=100 +42% F1 headline was sample-biased.** Items 0-99 of
   LongMemEval small are disproportionately single-session-user (the
   type SOMA wins biggest on). Full N=500 gives the honest +23%.
2. **Early "SOMA is 3000× faster than Mem0" framing was unfair.**
   Mem0 with `infer=True` is doing LLM-based semantic fact extraction
   at write time — a different operation than SOMA's "embed + insert."
   Apples to oranges. The fair comparison needs cloud-API LLM for
   Mem0 extraction at realistic speeds (~2-5 min/item vs SOMA's 1s).
3. **Verbose prompting was hiding SOMA's value on hard question types.**
   Multi-session and temporal-reasoning showed only +3-6% F1 lift
   with verbose prompts, because the 4B LLM wasted output budget on
   preamble ("Based on the conversation history..."). With strict
   prompting, these become +23-36% lifts.
4. **Cross-encoder rerank hurts on LongMemEval.** The cross-encoder
   was trained on short atomic doc pairs; LongMemEval's long
   multi-topic sessions confuse it. Rerank helps LoCoMo (short
   turns) but hurts LongMemEval (long sessions). Per-corpus choice.
5. **Plastic graph substrate ships but is inactive on retrieval
   workloads.** `rerank_weight=0.0` by default after ablation showed
   graph-rerank adds noise to ranked output. The "learns from use"
   story is an open research question, not a current claim.

## What's still open

1. **SOMA vs Mem0 head-to-head with Claude API** — Mem0's
   `infer=True` path is prohibitively slow on local LLMs. A fair
   comparison needs cloud-API extraction (~$15 for 100 items on
   haiku). Harness ready (`run_mem0_compare.py`), blocked on API key.
2. **Plastic graph activation test** — design doc exists
   (`docs/plans/2026-04-20-plastic-graph-activation-design.md`).
   Tests whether SOMA's graph actually improves over a multi-query
   session. Not yet run.
3. **Bigger-LLM strict-prompt N=500** — qwen3.5:9b run in progress
   to confirm the +23% SOMA advantage generalizes across LLM sizes
   at proper scale. Expected complete in ~90 min from now.
4. **Other embedders** — mxbai-embed-large showed larger retrieval
   deltas on LoCoMo. Would expect similar QA amplification but
   untested.

## Infrastructure built this session

- `benchmarks/industry/longmemeval/run_qa_compare.py` — retrieval
  comparison harness with 4 modes (chroma_cosine, chroma_rerank,
  soma_hybrid, soma_hybrid_rerank, full_context). Supports both
  Ollama and Anthropic providers, strict-prompt flag, resume-from-
  crash via per-item jsonl.
- `benchmarks/industry/longmemeval/run_mem0_compare.py` — SOMA vs
  Mem0 harness. Supports mem0_infer, mem0_raw, soma_hybrid.
- `benchmarks/industry/longmemeval/analyze_qa_compare.py` —
  pairwise win/loss + cost analysis.
- VRAM-safety defaults (`--sbert-device cpu`) to avoid co-loading
  embedder + large LLM on a 24GB card.
